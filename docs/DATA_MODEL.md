# EverDeliver — Data Model

## Purpose

Define persistent entities, statuses, and relationships. Phase 1 notification schema is locked in [ADR-0001](ADR/0001-phase1-persistence.md).

---

## Phase 1 (current)

PostgreSQL table `notifications` (Flyway `V1__create_notifications.sql`).

### Notification

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | Generated by API before insert |
| `channel` | VARCHAR | Phase 1 always `email` |
| `status` | VARCHAR | `QUEUED` \| `PROCESSING` \| `SENT` \| `FAILED` (`DEAD` reserved for Phase 2) |
| `recipient` | VARCHAR | Email (from request `email`) |
| `subject` | VARCHAR | Nullable |
| `body` | TEXT | From request `message` |
| `provider_message_id` | VARCHAR | Nullable; unused until Phase 3 |
| `retry_count` | INT | Default 0; unused until Phase 2 |
| `last_error` | VARCHAR(1024) | Set on `FAILED` (message only, truncated) |
| `created_at` | TIMESTAMPTZ | Set on insert |
| `updated_at` | TIMESTAMPTZ | Updated on every change |
| `sent_at` | TIMESTAMPTZ | Set when status becomes `SENT` |

**Indexes:** `(created_at DESC)`, `(status, created_at DESC)`.

**Not in Phase 1:** `campaign_id` (Phase 6).

## Status enum

```text
QUEUED → PROCESSING → SENT
              ↘
                FAILED → (retry Phase 2) → SENT
                          ↘ (exhausted) → DEAD
```
