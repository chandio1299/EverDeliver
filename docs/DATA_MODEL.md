# EverDeliver — Data Model

## Purpose

Define persistent entities, statuses, and relationships. Notification schema is locked in [ADR-0001](ADR/0001-phase1-persistence.md); retry/DLQ semantics in [ADR-0002](ADR/0002-phase2-retry-dlq.md).

---

## Phase 1–2 (current)

PostgreSQL table `notifications` (Flyway `V1__create_notifications.sql`).

### Notification

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | Generated by API before insert |
| `channel` | VARCHAR | Phase 1 always `email` |
| `status` | VARCHAR | `QUEUED` \| `PROCESSING` \| `SENT` \| `FAILED` \| `DEAD` |
| `recipient` | VARCHAR | Email (from request `email`) |
| `subject` | VARCHAR | Nullable |
| `body` | TEXT | From request `message` |
| `provider_message_id` | VARCHAR | Nullable; unused until Phase 3 |
| `retry_count` | INT | Default 0; incremented atomically when a retry is claimed (`FAILED → PROCESSING`). First attempt is not a retry. |
| `last_error` | VARCHAR(1024) | Set on `FAILED` (message only, truncated); retained when status becomes `DEAD` |
| `created_at` | TIMESTAMPTZ | Set on insert |
| `updated_at` | TIMESTAMPTZ | Updated on every change |
| `sent_at` | TIMESTAMPTZ | Set when status becomes `SENT` |

**Indexes:** `(created_at DESC)`, `(status, created_at DESC)`.

**Not in Phase 1:** `campaign_id` (Phase 6).

## Status enum

```text
QUEUED → PROCESSING → SENT
              ↘
                FAILED → (retry claim) PROCESSING → SENT
                          ↘ (exhausted or permanent) → DEAD
```

Retry/DLQ semantics: [ADR-0002](ADR/0002-phase2-retry-dlq.md). Permanent failures skip retry topics and go straight to `notification-topic-dlq` / `DEAD` (`retry_count` stays 0).
